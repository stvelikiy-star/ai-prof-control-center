## Безопасность очереди и восстановление

- Один глобальный lock `fcntl.flock`: запуск второй задачи исключён до завершения первой.
- Долговечное JSON-состояние: атомарная запись через временный файл, `os.fsync`, права 0600.
- Общий срок кампании 4 часа; timeout одного Codex worker 420 секунд; user systemd максимум 600 секунд.
- Прежде чем выполнять задачу, проверяются RAM (>= 1.5 ГБ), свободное место (disk <88%), состав очереди, разрешённый тип задания.
- При timeout worker и дочерние процессы убиваются через отдельную process group, без оставленного orphan Codex.
- Принудительное аварийное завершение отдельного тестового процесса `os._exit(78)` проверено: новый запуск не повторяет работу, переводит задачу в `interrupted` и ждёт reconciliation.
- Восстановление `running → completed` разрешено только при подтверждении PR, SHA, Draft/Not merged, двух файлов через GitHub API и локального итогового состояния/Telegram.
- Изменённый type/scope или поддельный SHA проваливают тесты и блокируют выполнение.
- Этапы не выполняют merges, деплой, произвольные команды issue или доступ к другим проектам.
