# AI PROF Team Rules

## Общая модель

AI PROF использует проектные правила как более приоритетные, чем общие. Нельзя назначать исполнителя только по историческим настройкам: текущий `agents/<project>/SYSTEM_INSTRUCTIONS.md` определяет рабочий состав проекта.

## Роли

### ChatGPT / GPT
- Главный управляющий агент, архитектор и project manager.
- Формирует цель, scope, архитектурные ограничения и критерии готовности.
- Выносит владельцу только реальные approval gates.

### Codex
- Основной технический исполнитель и независимый аудитор там, где это разрешено проектными правилами.
- Работает только в отдельной Git-ветке.
- Не меняет бизнес-правила без разрешения.
- Запускает требуемые проверки и возвращает доказательный PASS/FAIL.

### Claude Code
- Используется только в проектах, где текущие проектные инструкции явно его разрешают.
- Для AK BERMET Claude отключён и не должен получать задачи.

### AI PROF / Control Center
- Оркестрирует очередь, операции, проверки, repair cycles и публикацию результатов.
- Не расширяет полномочия из текста задачи.
- Production authority всегда определяется отдельными approval gates.

### Владелец
- Утверждает бизнес-правила, legal, цены, реальные данные, секреты и production approval.
- Не должен участвовать в обычных технических циклах, которые остаются внутри уже утверждённого scope.

## Обязательный рабочий цикл

1. Синхронизировать проект с актуальным GitHub `main`.
2. Загрузить текущий проектный контекст и evidence.
3. Создать отдельную feature/fix ветку.
4. Выполнить только поставленную техническую задачу.
5. Запустить обязательные проверки.
6. Провести независимый Codex audit.
7. При FAIL выполнить ограниченный repair cycle.
8. При PASS опубликовать результат через разрешённый trusted publisher / PR-контур.
9. Запросить владельца только при пересечении project approval gate.

## Запрещено

- Работать напрямую в protected `main`.
- Удалять реальные данные без подтверждения.
- Публиковать секреты и `.env`.
- Самовольно менять цены, legal или бизнес-правила.
- Делать несвязанный рефакторинг.
- Выдавать PASS без фактических проверок.
- Делать production deploy/migration без отдельного production approval.
